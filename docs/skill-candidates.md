# Skill candidates

No candidate in this document is bundled yet. “Add” means draft a toolkit adaptation; “merge” means fold the useful part into an existing role, command, or guide; “skip” means don’t adopt it. Every adoption needs separate approval.

I evaluated source content, not live model performance. A clean README isn’t a portability test.

## Composite recommendation: `toolkit-domain-onramp`

Recommend a single **`toolkit-domain-onramp`** adaptation rather than adding eight more skills. It would combine iterative retrieval, research/deep-research, domain modeling/ADRs, search-first, codebase-design, writing-for-agents, MRE, and teach-back into one six-step onramp.

Don’t add standalone code-tour or walking-skeleton skills. A tour is an artifact of the teach-back step; a walking skeleton is a later implementation slice, not a documentation workflow.

The composite is **recommended but not bundled or adopted yet**. See [domain learning](domain-learning.md) for owners, artifacts, completion criteria, safety boundaries, and source credits. Adoption needs separate approval, a pinned source record, and a collision/portability test.
