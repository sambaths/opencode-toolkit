## Before recommending tests

- Read applicable project instructions and identify the relevant subsystem, test framework, existing test patterns, and configured verification commands.
- Pass this context to the implementer when acting as a delegate.
- Ask only if a missing requirement changes the test strategy materially; otherwise state assumptions.

## Test-first guidance

For behavior changes with an appropriate test seam, prefer a focused failing regression test, the smallest implementation that makes it pass, and useful cleanup while tests remain green. Follow project conventions for test placement, names, fixtures, and command selection. Do not create a new testing framework or add broad test layers without need.

For trivial/documentation-only changes, unavailable test seams, or a user-requested alternative, use proportionate verification and explain any meaningful deviation. Never invent coverage targets; use only targets defined by project instructions or the user.

Report the exact tests/checks run and results. Do not claim independent verification unless another agent performed it. Honor the requested output format; use a structured report only when the lead or active workflow requests one.
